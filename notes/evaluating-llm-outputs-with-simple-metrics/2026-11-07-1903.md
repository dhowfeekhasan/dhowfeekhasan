### TIL: Evaluating LLM Outputs with Simple Metrics

Automated evaluation of LLM outputs often starts with deterministic string metrics before escalating to expensive LLM-as-a-judge pipelines. **Exact Match (EM)** checks strict equality (normalized for whitespace/case). **ROUGE-L** measures the longest common subsequence, capturing fluency and recall for summarization. **BERTScore** uses contextual embeddings to compute precision/recall/F1, detecting semantic equivalence despite lexical differences (e.g., "car" vs. "automobile"). These metrics are fast, interpretable, and require no API keys.

A critical workflow is **normalization** before comparison. Lowercasing, stripping punctuation/articles ("a", "the"), and fixing whitespace prevents false negatives from trivial formatting differences. For generation tasks, always report **aggregate statistics** (mean/median) across a test set, not single examples. High variance often indicates prompt instability rather than model capability.

```python
from rouge_score import rouge_scorer
from bert_score import score
import string

def normalize(text):
    return ' '.join(text.lower().translate(str.maketrans('', '', string.punctuation)).split())

pred = "The cat sits on the mat."
ref  = "A cat is sitting on the mat."

# 1. Exact Match (Normalized)
em = int(normalize(pred) == normalize(ref))

# 2. ROUGE-L F1
scorer = rouge_scorer.RougeScorer(['rougeL'], use_stemmer=True)
rouge_l = scorer.score(ref, pred)['rougeL'].fmeasure

# 3. BERTScore F1 (requires torch)
P, R, F1 = score([pred], [ref], lang="en", verbose=False)
bert_f1 = F1.mean().item()

print(f"EM: {em} | ROUGE-L: {rouge_l:.3f} | BERTScore: {bert_f1:.3f}")
# Output: EM: 0 | ROUGE-L: 0.571 | BERTScore: 0.921
```

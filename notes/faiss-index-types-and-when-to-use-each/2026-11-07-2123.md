### TIL: FAISS Index Types & Selection Guide

FAISS indexes trade off search speed, memory usage, and recall. **Flat indexes** (`IndexFlatL2`, `IndexFlatIP`) perform exhaustive search: 100% recall, zero training, but $O(N)$ latency. Use for $N < 100\text{k}$ or as a ground-truth baseline. **IVF (Inverted File)** indexes (`IndexIVFFlat`, `IndexIVFPQ`) cluster vectors into $nlist$ centroids; search probes only $nprobe$ clusters. They require training data and offer sub-linear speed. Use `IVFFlat` for exact vectors within clusters ($N \sim 1\text{M}$); use `IVFPQ` (Product Quantization) for massive compression ($N > 1\text{M}$) accepting slight recall loss. **HNSW** (`IndexHNSWFlat`) builds a proximity graph: logarithmic search complexity, high recall, no training needed, but high RAM overhead (graph edges). Best default for $N < 10\text{M}$ when latency matters. **PQ/SCANN** variants prioritize extreme compression for billion-scale.

Choose by constraints: **Accuracy first + small data** $\rightarrow$ `Flat`. **Speed + 1M–10M + RAM ok** $\rightarrow$ `HNSW`. **Huge scale + limited RAM** $\rightarrow$ `IVFPQ`. Always tune `nprobe` (IVF) or `efSearch` (HNSW) at query time to dial the speed/recall curve.

```python
import faiss, numpy as np

d, nb, nq = 128, 100000, 10
xb = np.random.random((nb, d)).astype('float32')
xq = np.random.random((nq, d)).astype('float32')

# HNSW: fast, accurate, no training, higher RAM
index = faiss.IndexHNSWFlat(d, 32)  # M=32 connections per node
index.hnsw.efConstruction = 40      # build-time accuracy
index.add(xb)
index.hnsw.efSearch = 16            # query-time speed/recall tradeoff
D, I = index.search(xq, k=5)
print(I[:2])  # top-5 indices for first 2 queries
```
